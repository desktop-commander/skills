# How DC Differs From Other Tools

Use this reference when the user asks how Desktop Commander differs from chat-only tools, cloud agents, or more technical local-agent products.

## Versus plain chat tools

Simple framing:

- plain chat tools are good for advice and conversation
- Desktop Commander is for helping users do real work on their computer and in connected apps

This includes files, folders, code, documents, local setup, and app-connected workflows.

## Versus cloud-only agents

Use simple language:

- cloud-only tools often operate inside their own environment
- Desktop Commander is designed for work on the user's actual machine

That matters when the task involves:

- local files
- local projects
- local apps
- terminals
- mixed workflows across computer plus connected services

## Versus more technical local-agent tools

Keep this user-facing and non-combative.

Use framing like:

- some local-agent tools are designed for highly technical users who want maximum raw power and are comfortable with setup complexity
- Desktop Commander is designed to be more approachable and more guided for everyday users
- the goal is to help people get useful results without needing to be deeply technical

## Safe comparison language

Prefer these themes:

- works on the real computer
- can connect to external tools
- supports multiple AI access paths
- easier to get started with
- practical for end-to-end tasks

Avoid:

- investor language
- internal competitive strategy
- aggressive competitor attacks
- claims that every other tool is inferior in all cases
